## 1. 目的・背景

- ネットワーク資格（まず CCNA 200-301）向けの問題演習アプリを、**iPhone で片手で使える形**で提供する。
- 出発点は、既存の演習サービス（Ping-t）が PC 向けのレイアウトで、スマホでは使いにくいという不満。
- 目標：「Ping-t レベルの問題演習を、通勤中に片手で」。App Store で公開する。
- あわせて、CIDR 計算やサブネットの設計など、**実際のネットワーク設計に使える計算機**を備える。問題を「解く」ことと、計算機で「確かめる・使う」ことを同じアプリで行き来できるようにする。

## 2. 対象ユーザーと利用シーン

| 項目 | 内容 |
|---|---|
| 主な利用者 | CCNA の受験を予定している社会人・学生（ネットワークの初学者〜中級者） |
| 利用シーン | 問題演習：通勤電車の中など、片手がふさがっていて数分しかないとき<br>計算機：学習中の検算、演習や実務でのアドレス設計・確認 |
| 利用時間 | 1回 3〜5分、1問 30秒程度 |
| 端末 | iPhone（縦向き） |

## 3. スコープ

### 3.1 MVP（v1.0）に含める

- サブネット計算問題の自動出題（5種類 × 難易度3段階）
- 手書き問題の出題（アプリに同梱。初期収録数は30問程度）
- 回答（すべて数字の入力）・正誤判定・解説表示
- 学習履歴の端末内保存と、間隔反復による復習出題
- 分野別の出題メニュー
- 成績画面（分野別の正答率など）
- 実用の計算機：CIDR 計算・サブネット分割・VLSM 設計・経路集約・進数変換（§4.3。U-07 で 5 種すべてに確定）

### 3.2 MVP に含めない（将来の検討事項）

- 課金（買い切り、または分野別課金。問題数がそろってから検討）
- ACL・ワイルドカードマスクなど、サブネット以外の自動生成問題
- アカウント登録、端末間の同期、クラウドへのバックアップ
- 復習リマインダーの通知
- iPad 向けのレイアウト最適化（iPad の互換モードで正しく動くことは必須。§5 を参照）
- CCNA 以外の資格
- 日本語以外の言語
- IPv6 の計算（U-08）
- 計算機の計算履歴の保存（U-09）

## 4. 機能要件

| ID | 機能 | 要件 | MVP |
|---|---|---|---|
| FR-01 | 出題 | 問題を1問ずつ表示する。問題文と入力欄を1画面に収める | ○ |
| FR-02 | 回答形式 | 回答はすべて、数字を自分で入力する形式とする。IP アドレスやサブネットマスクのように「.」を含む数字も入力で答える。選択式（単一選択・複数選択）は扱わない | ○ |
| FR-03 | 正誤判定 | 入力を整えて（空白を除き、全角の数字や「．」も半角とみなし、「,」も「.」とみなす）正解の文字列と一致したら正解 | ○ |
| FR-04 | 解説表示 | 回答後すぐに正誤・正解・解説を表示する | ○ |
| FR-05 | サブネット問題の自動生成 | 次の5種類を生成する：ネットワークアドレス／ブロードキャストアドレス／ホスト数／プレフィックス長→サブネットマスク／最後のホストアドレス。答えは入力させる（選択肢は作らない） | ○ |
| FR-06 | 問題の再現 | 自動生成問題は ID（seed を含む）から同じ問題を再生成できる | ○ |
| FR-07 | 難易度 | 基礎・標準・応用の3段階。サブネット問題は難易度ごとにプレフィックス長の範囲を変える | ○ |
| FR-08 | 手書き問題の収録 | 手書き問題はアプリに同梱するデータ（JSON）から読み込む。答えが数字になる問題だけを収録する | ○ |
| FR-09 | 学習履歴の記録 | 回答ごとに、正誤と回答日時を端末内に保存する | ○ |
| FR-10 | 間隔反復 | 間違えた問題は翌日に、正解した問題は間隔を広げて再出題する（SM-2 の簡略版） | ○ |
| FR-11 | 復習優先 | 学習を始めたとき、復習日を迎えた問題を新しい問題より先に出す | ○ |
| FR-12 | 分野別出題 | CCNA 200-301 の6分野と「サブネット計算ドリル」から出題範囲を選べる | ○ |
| FR-13 | 成績表示 | 全体と分野別に、回答数・正答率・今日の復習予定数を表示する | ○ |
| FR-14 | 学習履歴のリセット | 確認のうえ、学習履歴をすべて削除できる | ○ |
| FR-15 | 中断 | 学習の途中でやめられる。それまでの回答は履歴に残す | ○ |
| FR-16 | 計算機メニュー | 学習とは別に、計算機をまとめた入口（タブ「計算」）から各計算機を使える | ○ |
| FR-17 | CIDR 計算 | IPv4 アドレスとプレフィックス長（またはサブネットマスク）から、ネットワーク情報を一度に求める（§4.3） | ○ |
| FR-18 | サブネット分割 | ネットワークを、分割数または 1 サブネットに必要なホスト数で等分し、一覧を出す（§4.3） | ○ |
| FR-19 | VLSM 設計 | 親ネットワークと、用途ごとの必要ホスト数から、無駄の少ないサブネットを割り当てる（§4.3） | ○ |
| FR-20 | 経路集約 | 複数のネットワークをまとめる集約ルートを求める（§4.3） | ○ |
| FR-21 | 進数変換 | IPv4 アドレスやマスクを 10 進・2 進・16 進で相互に変換する（§4.3） | ○ |
| FR-22 | 計算の過程 | 計算機の結果に「解き方」（ブロックサイズ、AND の取り方など）を添えて、学習につなげる | ○ |
| FR-23 | 問題から計算機へ | サブネット問題の解説から、その問題の値を入れた CIDR 計算を開ける | ○ |
| FR-24 | 結果のコピー | 計算結果の各値をコピーできる（設計資料などに貼れる） | ○ |

### 4.1 出題分野（CCNA 200-301 に準拠）

| domain | 表示名 |
|---|---|
| network-fundamentals | ネットワークの基礎 |
| network-access | ネットワークアクセス |
| ip-connectivity | IP 接続 |
| ip-services | IP サービス |
| security-fundamentals | セキュリティの基礎 |
| automation-programmability | 自動化とプログラマビリティ |

### 4.2 1回の学習の問題数

- 1回の学習は **10問**とする。途中でやめることもできる（FR-15）。

### 4.3 計算機の入力と出力

対象は IPv4 のみ（IPv6 は U-08）。

| ID | 計算機 | 入力 | 出力 |
|---|---|---|---|
| FR-17 | CIDR 計算 | IPv4 アドレス ＋ プレフィックス長（`/0`〜`/32`）またはサブネットマスク | ネットワークアドレス、ブロードキャストアドレス、サブネットマスク、ワイルドカードマスク、使えるホストの範囲（最初〜最後）、使えるホスト数、アドレスの総数、2 進数表示（ネットワーク部とホスト部を分けて示す）、アドレスの種別（プライベート・ループバックなど） |
| FR-18 | サブネット分割 | ネットワーク（CIDR）＋ 分割数 または 1 サブネットに必要なホスト数 | 分割後のプレフィックス長、1 サブネットのホスト数、サブネットの一覧（ネットワーク・ホストの範囲・ブロードキャスト）。一覧が多いときの表示件数の上限は基本設計で決める |
| FR-19 | VLSM 設計 | 親ネットワーク（CIDR）＋ 用途名と必要ホスト数の組（複数） | 必要ホスト数の多い順に割り当てたサブネット（用途名・CIDR・ホストの範囲・使える数と必要数）、使わずに残った範囲。入りきらないときは、その旨と足りない量 |
| FR-20 | 経路集約 | 複数のネットワーク（CIDR） | すべてを含む最小の集約ルート（CIDR）と、集約によって余分に含まれる範囲 |
| FR-21 | 進数変換 | IPv4 アドレスまたはマスク（10 進・2 進・16 進のどれでも） | 10 進・2 進・16 進の表記。オクテットごとに区切って示す |

- `/31` と `/32` も扱う。`/31` はポイントツーポイント用に 2 アドレスとも使える（RFC 3021）、`/32` は 1 台のホストを指すものとして示す。

## 5. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 操作性 | 回答・次へ進むなど学習中の主な操作を、片手（親指）で届く画面下半分に置く |
| NFR-02 | 操作性 | 1問を 30秒程度で解き終えられる。回答から次の問題までの操作は、タップ1回で済む |
| NFR-03 | 性能 | アプリを起動してから1問目が出るまで 2秒以内（目標値）。問題の切り替えは待ち時間なく行う |
| NFR-04 | オフライン | すべての機能を通信なしで使える |
| NFR-05 | プライバシー | 学習履歴は端末内にだけ保存し、外部に送信しない。App Privacy の申告は「データを収集しません」とする |
| NFR-06 | 権限 | OS の権限（位置情報・通知・カメラなど）を一切要求しない |
| NFR-07 | 対応環境 | iOS 17 以上の iPhone、縦向き。iPad の互換モードでもクラッシュせず、すべての機能を使える |
| NFR-08 | アクセシビリティ | Dynamic Type（文字サイズの変更）、ダークモード、VoiceOver に対応する |
| NFR-09 | 信頼性 | 学習の途中でアプリを終了しても、それまでの回答履歴を失わない |
| NFR-10 | 正確性 | サブネット問題の正解と計算機の結果は計算で求め、誤りがないこと（標準的なライブラリの計算結果と大量の値で照合して確かめる） |
| NFR-11 | 保守性 | 問題データを差し替えるだけで（コードを変えずに）手書き問題を追加・修正できる |
| NFR-12 | 言語 | 日本語のみ |
| NFR-13 | 計算機の入力 | 全角の数字・空白を受け付け、「,」は「.」とみなす。マスクは `/26` と `255.255.255.192` のどちらでも入力できる。誤った入力は、どこが誤りかをその場で示す。結果は入力に合わせてすぐ更新する（計算ボタンを押させない） |

## 6. コンテンツ・法務の要件

| ID | 要件 |
|---|---|
| LR-01 | Ping-t や市販の参考書の問題・解説を、転載したり改変したりして使わない（著作権） |
| LR-02 | 実際の試験問題を再現しない（ブレインダンプの禁止。Cisco の受験規約に違反する） |
| LR-03 | 問題はすべてオリジナルとする。AI で下書きした問題も、技術的に正しいか人が確認してから収録する |
| LR-04 | 「CCNA」「Cisco」はアプリ名の先頭に置かない。サブタイトルや説明文で「CCNA対策」のように説明として使う |
| LR-05 | アプリ名に「Ping」を含めない（Ping-t との混同を避ける） |
| LR-06 | プライバシーポリシーを用意し、App Store とアプリ内から見られるようにする |

## 7. 制約・前提

- 開発は SwiftUI、iOS 17 以上。サーバーは持たない。
- 公開は App Store。ビルドとアップロードは Xcode Cloud を使う想定（他の自作アプリと同じ運用）。
- アプリ名（仮）：ネトレ - ネットワーク資格ドリル／サブタイトル（仮）：通勤1問、CCNA対策をスキマ時間で。
  App Store Connect での仮登録と、J-PlatPat での商標検索がまだ済んでいない。
