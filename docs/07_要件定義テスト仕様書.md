## 1. 環境

| 区分 | 内容 |
|---|---|
| 端末 A（基準） | iPhone の実機。iOS 17 以上の最新の公開版。地域「日本」、言語「日本語」。TestFlight のビルド |
| 端末 A'（大きい機種） | 片手操作の確認用に、対応機種のうち画面がいちばん大きいもの（Pro Max など） |
| 端末 A''（古い機種） | 起動時間の確認用に、手元にある iOS 17 対応機のうちいちばん古いもの |
| 端末 B | iOS 17.0 のシミュレーター（Xcode に 17.0 のランタイムを入れる）。TestFlight のビルドはシミュレーターで動かないので、候補ビルドと同じコミットをローカルでビルドする |

| 地域設定の確認 | 端末 A の地域を「ドイツ」に変えて行う回（小数点キーが「,」になる） |
| ネットワーク | 機内モード（通信なし）で行う回と、通常の回。機内モードの回は、コントロールセンターで Wi-Fi・Bluetooth もオフになっていることを確かめる |
| 外部の検算 | IP の値は Python の `ipaddress` で確かめる（アプリ自身の計算機は使わない。同じコードを使うため誤りを見逃す）。アドレスの種別は `is_private` などの判定がアプリの種別と一致しないので、`is_loopback`・`is_link_local`・`is_multicast` と、`in ip_network(...)`（100.64.0.0/10・0.0.0.0/8・240.0.0.0/4・10/8・172.16/12・192.168/16）で 1 つずつ確かめる |
| 記録 | テストごとに結果（合格・不合格・対象外）、日付、ビルド番号、スクリーンショットまたは画面の録画を記録表に残す |

## 7. 合格の基準

- ST-25 と ST-26 の a ＋ b（目標値）を除き、すべての試験が合格または「対象外（理由を記録）」であること。
- 目標値に届かないときは、原因と対応をレビューで判断する。
- 不合格があれば、原因を直して該当の単体・結合テストを足し、その試験をやり直す。
