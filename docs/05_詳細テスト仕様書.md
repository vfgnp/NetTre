## 1. 方針

| 項目 | 内容 |
|---|---|
| 道具 | Swift Testing（`@Test`・`#expect`）。パラメータ化テスト（`arguments:`）で多数の値をまとめて回す |
| 対象 | Models・Services・Generators・Calculators・ViewModels（View は対象外。06 の UI テストで見る） |
| 時刻と暦 | `now` は固定の日時（2026-10-18 08:00 JST）。`Calendar` は `Asia/Tokyo` のグレゴリオ暦を作り、`ReviewState.record`・`ReviewStore`・`SessionBuilder` に必ず渡す（詳細設計 §12.1） |
| 保存 | `ModelContainer(isStoredInMemoryOnly: true)` で毎テスト新しく作る。保存の失敗は `ReviewRecording` の失敗する実装で起こす（§12.2） |
| 問題データ | `QuestionRepository(data:assertOnFailure: false)` にテスト用の JSON を直接渡す（§12.3。デバッグビルドの assert で止めない） |
| 乱数 | `SeededRNG(seed:)` を渡して結果を固定する。重なりを起こすテストには、`SeededRNG(seed: 7)` が返す数列の先頭 k 個（k = 1 問を作るのに使う `next()` の回数。種類と seed で 2）を 2 回くり返してから続きを返すスタブの RNG を使う（棄却されない普通の値なので、`random(in:)` が止まらなくなることはない） |
| 小数の比較 | `ease`・正答率は `abs(a − b) < 1e-9` で比べる。上限 3.0・下限 1.3 は `min`・`max` で丸めるので完全一致を期待する |
| 照合用データ | `NetTreTests/Fixtures/` の JSON（`scripts/gen_fixtures.py` が作る。seed 固定） |
| 合格の基準 | 全ケース合格。照合用データとの一致 100%。Calculators・Services・Models の行カバレッジ 90% 以上 |
