## 3. ドメインモデル

### 3.1 Question（改修）

選択式をやめたので、`kind`・`choices` を削除し、`answer` を文字列 1 つにする。

```swift
enum Domain: String, Codable, CaseIterable {
    case networkFundamentals = "network-fundamentals"
    case networkAccess = "network-access"
    case ipConnectivity = "ip-connectivity"
    case ipServices = "ip-services"
    case securityFundamentals = "security-fundamentals"
    case automationProgrammability = "automation-programmability"
    var displayName: String   // 「ネットワークの基礎」など（要件定義 §4.1）
    var idPrefix: String      // "net-fund" など（基本設計 §5.1）
}

enum Difficulty: Int, Codable, CaseIterable, Comparable { case basic = 1, standard = 2, advanced = 3 }

struct Question: Codable, Identifiable, Hashable {
    let id: String
    let domain: Domain
    let tags: [String]
    let difficulty: Difficulty
    let stem: String
    let answer: String          // 正解の文字列 1 つ
    let explanation: String     // Markdown
    let version: Int

    var isGenerated: Bool { id.hasPrefix("gen-subnet-") }
    var keyboard: AnswerKeyboard { AnswerKeyboard(for: answer) }
    func isCorrect(_ input: String) -> Bool {
        AnswerNormalizer.normalize(input) == AnswerNormalizer.normalize(answer)
    }
}

enum AnswerKeyboard { case number, decimal    // .numberPad / .decimalPad
    init(for answer: String)   // 数字だけ → .number、数字と「.」だけ → .decimal
}
```

- D11（採用）：**手書き問題の JSON 形式を変える**。`kind`・`choices` をなくし、`answer` を配列から文字列にする（例：`"answer": "110"`）。既存の `questions_sample.json` は実装時にこの形式へ直す（選択式の 2 問は数字で答える問題に作り直す）。
- 正解が数字と「.」以外を含む問題は収録しない（要件定義 FR-08）。`QuestionRepository` の読み込み時にデバッグビルドで検査する（§6.2）。

### 3.2 AnswerNormalizer

```swift
enum AnswerNormalizer {
    static func normalize(_ s: String) -> String
}
```

次の順で整える（基本設計 §6.3）。

1. `s.applyingTransform(.fullwidthToHalfwidth, reverse: false)` で全角を半角にする
2. `","` を `"."` にする
3. 空白（`Character.isWhitespace`）を除く
4. 小文字にする

### 3.3 ReviewState（D2 を反映）

```swift
struct ReviewState: Codable, Equatable {
    var interval: Int = 0
    var ease: Double = 2.5
    var streak: Int = 0
    var dueDate: Date

    mutating func record(correct: Bool, now: Date, calendar: Calendar = .current)
}
```

- 正解：`streak += 1`。`interval` は streak 1 → 1、2 → 3、3 以上 → `Int((Double(interval) * ease).rounded())`。`ease = min(ease + 0.1, 3.0)`。
- 不正解：`streak = 0`、`interval = 1`、`ease = max(ease - 0.2, 1.3)`。
- `dueDate = calendar.date(byAdding: .day, value: interval, to: calendar.startOfDay(for: now))`（D2：日付単位）。
- 出題の対象かどうかは `dueDate <= now` で判定する。

### 4.1 ReviewStore

```swift
@MainActor final class ReviewStore {
    init(context: ModelContext)
    func recordAnswer(question: Question, correct: Bool, now: Date) throws
    func dueRecords(in scope: SessionScope, now: Date) throws -> [ReviewRecord]   // dueDate の古い順
    func answeredQuestionIds() throws -> Set<String>
    func summary(now: Date) throws -> StatsSummary
    func deleteAll() throws
}
```

`recordAnswer` の処理（回答のたびにすぐ保存する。NFR-09）：

1. `AnswerLog` を 1 件追加する。
2. 手書き問題：`ReviewRecord` がなければ作り、`ReviewState.record` の結果を書き戻す。`questionVersion` を今の version に更新する（D4）。
3. 自動生成問題（D3）：
   - `ReviewRecord` がない：不正解なら作る。正解なら作らない。
   - `ReviewRecord` がある：`record` を反映し、正解で `streak >= 2` になったら削除する。
4. `context.save()`。失敗したら例外を返し、画面は学習を続けて短い表示を出す（§8）。

`StatsSummary`：回答数・正答率（全期間）、今日の復習数（`dueDate <= now`）、今日解いた数（今日の 0:00 以降の `AnswerLog`）、分類ごとの回答数と正答率。分類は「サブネット計算」（`isGenerated`）と 6 分野（`isGenerated == false` の `domainRaw`）。

### 5.3 SessionBuilder

```swift
enum SessionScope: Hashable { case mixed, domain(Domain), subnetDrill(Difficulty) }

struct SessionBuilder {
    func build(scope: SessionScope, now: Date, store: ReviewStore,
               repository: QuestionRepository, rng: inout some RandomNumberGenerator) throws -> [Question]
}
```

1. 復習：`store.dueRecords(in: scope, now:)` から最大 10 問。`repository.question(id:)` が nil のもの（削除された手書き問題）は飛ばす。
   - `.domain(d)`：手書きで `domain == d` のものだけ
   - `.subnetDrill(level)`：自動生成で ID の difficulty が `level` のものだけ
   - `.mixed`：すべて
2. 新しい問題で 10 問まで埋める（復習と同じ ID は入れない）。
   - `.mixed`：残り r 問のうち `r / 2`（切り捨て）を自動生成、残りを未回答の手書き問題（並び順）。手書きが足りなければ自動生成で埋める。
   - `.domain(d)`：未回答の手書き問題（並び順）。足りなければ届いた数だけ。
   - `.subnetDrill(level)`：自動生成のみ。
3. 自動生成：種類は `SubnetQuestionType.allCases.randomElement(using:)`、seed は `UInt64.random(in: 1...999_999_999, using:)`。難易度は `.mixed` では `.standard`、`.subnetDrill` では選ばれた難易度。
4. 結果が 0 問なら空配列を返し、画面は「この分野の問題はまだありません」を出す。

## 6. 計算機

### 6.1 IPv4・Subnet（既存を拡張）

```swift
struct IPv4: Hashable, Comparable, CustomStringConvertible {
    let value: UInt32
    var octets: [UInt8]
    var binaryString: String          // "11000000.10101000.00001010.01001101"
    var hexString: String             // "C0.A8.0A.4D"
}

struct Subnet: Hashable {
    let address: IPv4                 // 入力されたアドレス（ホスト部を含む）
    let prefix: Int                   // 0...32
    var mask: IPv4; var wildcard: IPv4
    var network: IPv4; var broadcast: IPv4
    var totalAddresses: UInt64        // 2^(32-prefix)
    var usableHosts: UInt64           // /0〜/30：total-2、/31：2、/32：1
    var firstHost: IPv4; var lastHost: IPv4   // /31：network と broadcast、/32：address
    var cidrString: String            // "192.168.10.64/26"（network を使う）
}
```

- マスクは `prefix == 0 ? 0 : UInt32.max << (32 - prefix)`。
- 計算はすべて `UInt32`／`UInt64` の整数演算。足し算は `&+` を使わず、範囲を確かめてから行う（オーバーフローでの異常終了を防ぐ）。

### 6.2 IPv4InputParser（NFR-13）

```swift
enum InputError: Error, Equatable {
    case empty
    case octetCount(Int)              // 「4 つの数をピリオドで区切って入力してください」
    case octetRange(index: Int, value: Int)   // 「第3オクテットが 256 です（0〜255）」
    case notNumber(index: Int)
    case prefixRange(Int)             // 「プレフィックス長は 0〜32 です」
    case maskNotContiguous            // 「マスクの 1 が連続していません」
    case invalidPrefix                // 数字でもマスクでもない（"-1"・"abc"）。「プレフィックス長は 0〜32 の数かマスクで入力してください」（v1.1）
    case invalidRadix                 // 進数変換で読めない（v1.1）
    var message: String
}

enum IPv4InputParser {
    static func address(_ s: String) -> Result<IPv4, InputError>
    static func prefixOrMask(_ s: String) -> Result<Int, InputError>  // "26" または "255.255.255.192"
    static func splitPasted(_ s: String) -> (address: String, prefix: String)?  // "a.b.c.d/n" と "a.b.c.d m.m.m.m" を分ける（整形の前に「/」または空白で分ける。v1.1）
}
```

- 入力は先に `AnswerNormalizer.normalize` で整える（全角・「,」・空白）。
- オクテットの先頭の 0（`010`）は 10 として受け付ける（8 進数とはみなさない）。
- マスクの連続判定：`~mask &+ 1` が 2 の累乗（または 0）であること。

### 6.3 CIDRCalculator（FR-17）

```swift
struct CIDRResult { let subnet: Subnet; let kind: AddressKind; let steps: [String] }
enum CIDRCalculator { static func calculate(address: IPv4, prefix: Int) -> CIDRResult }

enum AddressKind { case `private`, loopback, linkLocal, sharedAddress, multicast, reserved, global
    init(_ address: IPv4)   // 判定の順：loopback(127/8) → private(10/8・172.16/12・192.168/16)
                            // → linkLocal(169.254/16) → sharedAddress(100.64/10)
                            // → multicast(224/4) → reserved(240/4・0/8) → global
}
```

### 6.4 CIDRBlocks（共通）

範囲 `[start, end]`（両端を含む、`UInt64` で扱う）を、境界のそろった最大の CIDR のまとまりに分ける。

```
while start <= end:
    size = start の末尾の 0 ビットから決まる最大の 2 の累乗（start = 0 なら 2^32）
    while start + size - 1 > end: size /= 2
    出力 (start, 32 - log2(size))
    start += size
```

VLSM の空き（§6.6）と経路集約の余分な範囲（§6.7）で使う。

### 6.5 SubnetSplitter（FR-18）

```swift
enum SplitMode { case count(Int), hosts(Int) }
struct SplitResult {
    let newPrefix: Int; let hostsPerSubnet: UInt64
    let totalCount: UInt64; let subnets: [Subnet]      // 先頭 splitDisplayLimit 件まで（D6）
    let roundedCount: Int?                             // 5 分割 → 8 のとき 8
}
enum SplitError: Error { case tooSmall, invalidNumber, exceedsParent }
enum SubnetSplitter { static func split(_ parent: Subnet, mode: SplitMode) -> Result<SplitResult, SplitError> }
```

- `.count(n)`（n ≥ 1）：`bits = ⌈log2 n⌉`、`newPrefix = parent.prefix + bits`。32 を超えたら `.tooSmall`。n が 2 の累乗でなければ `roundedCount = 2^bits`。
- `.hosts(h)`（h ≥ 1）：`size = h + 2 以上の最小の 2 の累乗`、`newPrefix = 32 - log2(size)`。`newPrefix < parent.prefix` なら `.exceedsParent`。
- `totalCount = 2^(newPrefix - parent.prefix)`。一覧は `parent.network` から `size` ずつ進めて作る。

### 6.6 VLSMPlanner（FR-19）

```swift
struct VLSMRequirement: Identifiable { let id: UUID; var name: String; var hosts: Int }
struct VLSMAllocation { let requirement: VLSMRequirement; let subnet: Subnet }
struct VLSMPlan { let allocations: [VLSMAllocation]; let freeBlocks: [Subnet] }
enum VLSMError: Error { case shortage(UInt64), invalidHosts(name: String), tooMany }
enum VLSMPlanner { static func plan(parent: Subnet, requirements: [VLSMRequirement]) -> Result<VLSMPlan, VLSMError> }
```

1. 件数が `vlsmMaxRequirements` を超えたら `.tooMany`。hosts < 1 があれば `.invalidHosts`。
2. 各要件のブロックの大きさ = `h + 2 以上の最小の 2 の累乗`。
3. 大きさの合計が親の `totalAddresses` を超えたら `.shortage(合計 − 親の総数)`。
4. 必要ホスト数の多い順（同じなら入力順。安定ソート）に、親の `network` から順に割り当てる。大きい順なので各ブロックは境界がそろう。
5. 残り `[cursor, parent.broadcast]` を `CIDRBlocks` で空きに分ける。

### 6.7 RouteSummarizer（FR-20）

```swift
struct SummaryResult { let route: Subnet; let extraRanges: [Subnet]; let normalizedHostBits: Bool }
enum RouteSummarizer { static func summarize(_ networks: [Subnet]) -> Result<SummaryResult, SummaryError> }
```

1. 0 件・`summaryMaxNetworks` 超はエラー。各入力はホスト部を 0 にそろえ、そろえたものがあれば `normalizedHostBits = true`。
2. `low = 最小の network`、`high = 最大の broadcast`。`p = (low ^ high).leadingZeroBitCount`（32 ビットとして）。`route = Subnet(low & mask(p), p)`。
3. 入力の範囲を並べて重なりをまとめ、`route` の範囲から除いた隙間を `CIDRBlocks` で分ける（`extraRangesDisplayLimit` まで）。

### 6.8 RadixConverter（FR-21、D9）

```swift
enum Radix { case decimal, binary, hex }
struct RadixResult { let detected: Radix; let value: IPv4 }   // 表示は IPv4 の各プロパティで
enum RadixConverter { static func convert(_ input: String) -> Result<RadixResult, InputError> }
```

見分け方（入力は `AnswerNormalizer` で整えてから）：

1. `0x` で始まる、または a〜f を含む → 16 進。`0x` を外し、「.」区切りなら各 1〜2 けた × 4、区切りなしなら 8 けた。
2. 「.」区切りの 4 つが各 8 けたの 0/1、または区切りなしの 32 けたの 0/1 → 2 進。
3. それ以外 → 10 進（`IPv4InputParser.address`）。

### 6.9 CalculationSteps（FR-22）

```swift
enum CalculationSteps {
    static func cidr(_ s: Subnet) -> [String]
    static func split(_ r: SplitResult, parent: Subnet) -> [String]
    static func vlsm(_ plan: VLSMPlan) -> [String]
    static func summary(_ r: SummaryResult) -> [String]
}
```

`cidr` の文（プレフィックス長が 8 の倍数でないとき。`i = prefix / 8` が区切りのオクテット、`b = 256 >> (prefix % 8)` がブロックサイズ、`v` がそのオクテットの値）：

1. 「区切りは第 (i+1) オクテット。ブロックサイズは b」
2. 「v は b の ⌊v/b⌋ 倍〜⌊v/b⌋+1 倍の間なので、ネットワークは .(⌊v/b⌋×b)」

8 の倍数のときは「オクテットの境目なので、第 (i+1) オクテットから後ろを 0 にする」の 1 文。ただし /32 は「ホスト部がないので、アドレスそのものがネットワーク」、/0 は「すべてのビットがホスト部なので、ネットワークは 0.0.0.0」とする（v1.1）。

## 7. 画面と ViewModel

### 7.1 タブと遷移

- `RootTabView`：`TabView` に 4 タブ。各タブは `NavigationStack`。
- S-03 出題は `fullScreenCover`（タブバーを隠す）。S-04 は出題を閉じたあとに同じカバーの中で表示する。

### 7.2 QuizSessionViewModel（S-03・S-04）

```swift
@Observable @MainActor final class QuizSessionViewModel {
    enum Phase { case answering, answered(correct: Bool), finished }
    private(set) var questions: [Question]
    private(set) var index: Int
    var input: String
    private(set) var phase: Phase
    private(set) var outcomes: [(question: Question, correct: Bool, input: String)]
    var saveFailed: Bool                    // 保存に失敗したら true（短い表示を出す）

    var current: Question? ; var progressText: String     // "3 / 10"
    var canSubmit: Bool { !AnswerNormalizer.normalize(input).isEmpty }
    func submit()      // 判定 → outcomes に追加 → store.recordAnswer → phase = .answered
    func next()        // 最後なら .finished、それ以外は index += 1・input = ""・phase = .answering
    func quit()        // 回答が 0 件なら閉じる、1 件以上なら .finished
}
```

- 入力欄は `@FocusState` で、`phase == .answering` になるたびにフォーカスを当てる（キーボードが出る）。回答したらフォーカスを外す（キーボードを閉じる）。
- 「回答する」は `.safeAreaInset(edge: .bottom)` に置き、キーボードのすぐ上に来るようにする。
- 触覚フィードバックは `.sensoryFeedback(.success / .error, trigger:)`。
- 解説は `AttributedString(markdown:)` で表示する（失敗したら素の文字列）。

### 7.3 計算機の ViewModel

- 入力は `String` で持ち、`didSet` ではなく計算プロパティで結果を出す（入力が変わるたびに再計算。計算は軽い）。
  ```swift
  @Observable final class CIDRCalculatorViewModel {
      var addressText = ""; var prefixText = ""
      var result: Result<CIDRResult, InputError>? { … }   // 両方空なら nil（何も表示しない）
      func paste(_ s: String)            // IPv4InputParser.splitPasted で 2 つの欄に分ける
      func stepPrefix(_ delta: Int)      // −／＋。0〜32 に収める
  }
  ```
- VLSM と経路集約は行の配列（`[VLSMRequirement]`、`[NetworkRow]`）を持つ。追加は上限で無効にする。
- コピー：`UIPasteboard.general.string = 値`。画面の下に「コピーしました」を `copyToastDuration` 秒出す。

## 12. テストのための仕組みと細部の決まり（v1.1）

テスト仕様書（05〜07）の第三者レビューで、テストが成り立たない・決まっていないと指摘された点をここで決める。§3〜§9 と食い違うときは、この節を優先する。

### 12.1 時刻・暦・乱数を外から渡す

```swift
struct AppEnvironment {
    var now: () -> Date = { Date() }
    var calendar: Calendar = .current
    var makeRNG: () -> any RandomNumberGenerator = { SystemRandomNumberGenerator() }
}
```

- `NetTreApp` で 1 つ作り、ViewModel・`ReviewStore`・`SessionBuilder` に渡す。日付の計算（`startOfDay`・翌日）はすべてこの `calendar` を使う。
- `ReviewStore.init(context:calendar:)` とし、`recordAnswer`・`dueRecords`・`summary` はこの calendar で日付を扱う。
- テストは `calendar` に `Asia/Tokyo` の `Calendar(identifier: .gregorian)`、`now` に固定の日時、RNG に `SeededRNG` を渡す。

### 12.2 差し替えられる境界（protocol）

```swift
protocol ReviewRecording: AnyObject {
    func recordAnswer(question: Question, correct: Bool, now: Date) throws
    func dueRecords(in scope: SessionScope, now: Date) throws -> [ReviewRecord]
    func answeredQuestionIds() throws -> Set<String>
    func summary(now: Date) throws -> StatsSummary
    func deleteAll() throws
}
final class ReviewStore: ReviewRecording { … }
```

ViewModel と `SessionBuilder` は `ReviewRecording` を受け取る。テストは保存に失敗する実装を渡せる。

### 12.3 QuestionRepository の検査と失敗時の動き

```swift
struct ValidationIssue: Equatable { enum Kind { case duplicateId, invalidIdFormat, invalidAnswer }; let kind: Kind; let id: String }
final class QuestionRepository {
    init(data: Data?, assertOnFailure: Bool = true)    // テストは data を直接渡し、assertOnFailure: false
    convenience init(bundle: Bundle = .main)
    static func validate(_ questions: [Question]) -> [ValidationIssue]
    private(set) var loadFailed: Bool
}
```

- 読み込みに失敗したときや `validate` が誤りを返したとき、`assertOnFailure` が true（アプリ・デバッグビルド）なら `assertionFailure`。false なら止めない。`loadFailed` は JSON として読めなかったときだけ true で、検査の誤りは `issues` に残す（§12.13）。

### 12.4 学習の組み立ての細部

- 復習の並び：`dueDate` の古い順。同じ日時なら `questionId` の昇順。
- 新しい問題の並び：復習の後ろに、手書き → 自動生成 の順で置く。
- 自動生成の ID が 1 回の中で重なったら、seed を引き直す（最大 100 回）。
- 復習の記録を飛ばした分（問題がない ID）は、新しい問題で埋める。

### 12.5 自動生成問題の範囲と、問題から値を取り出す API

- プレフィックス長：基礎は 8・16・24 のどれか、標準は 24〜30、応用は 17〜30。
- アドレス：10.x.x.x・172.16〜31.x.x・192.168.x.x のどれか。第 2 オクテット以降の乱数は 1〜254（172 の第 2 オクテットは 16〜31）。
- `SubnetQuestionGenerator.subnet(fromId:) -> Subnet?`：ID から、その問題の元になったアドレスとプレフィックス長を返す（5 種類すべて）。FR-23 の「計算機で確かめる」はこれで S-08 に値を渡す。ホスト数・マスクの問題も、元のアドレスを入れて開く。

### 12.6 成績の型

```swift
struct CategoryStats: Equatable { let answered: Int; let correct: Int
    var rate: Double? { answered == 0 ? nil : Double(correct) / Double(answered) } }  // 0 件は nil（「まだ回答していません」）
struct StatsSummary: Equatable {
    let total: CategoryStats; let subnet: CategoryStats; let byDomain: [Domain: CategoryStats]
    let dueToday: Int; let answeredToday: Int }
```

- 画面の % は `Int((rate * 100).rounded())`（四捨五入）。

### 12.7 ViewModel の状態の追加

- `QuizSessionViewModel.Phase` に `.empty`（問題が 0 件）を足す。`shouldDismiss: Bool` を持ち、`quit()` で回答 0 件なら true にする（View はこれを見て閉じる）。
- サブネット分割の `hostsPerSubnet` は `Subnet.usableHosts` と同じ値（分割数で /31・/32 になったときは 2・1）。

### 12.8 計算機の誤りの細部

- `RouteSummarizer` の誤り：`enum SummaryError { case empty, tooMany }`。
- `CIDRBlocks`：`static func blocks(from start: UInt64, to end: UInt64, limit: Int) -> (blocks: [Subnet], truncated: Bool)`。
- プレフィックス欄の `"-1"`・`"abc"` は `.invalidPrefix`、`"33"` は `.prefixRange(33)`。

### 12.9 UI テスト用の起動引数（デバッグビルドだけ）

| 引数 | 動き |
|---|---|
| `-uitest` | 固定の日時（2026-10-18 08:00）、`Asia/Tokyo`、固定 seed、テスト用の問題データ、メモリ上の学習履歴。起動時に `UserDefaults`（難易度の記憶など）を初期化する |
| `-uitestPersistentStore` | 学習履歴をファイルに保存する（強制終了のテスト用） |
| `-uitestResetStore` | 起動時に保存ファイルを消す |
| `-uitestFailModelContainer` | 起動時に 1 回目に作るファイル保存の ModelContainer だけを失敗させる（代わりのメモリ上のコンテナは作れる。「履歴を消して作り直す」での作成は成功する） |
| `-uitestBrokenQuestions` | 壊れた問題データを `assertOnFailure: false` で読ませる（デバッグビルドでも止めない） |
| `-uitestKeepDefaults` | `-uitest` でも `UserDefaults` を初期化しない（記憶の確認用） |
| `-uitestDay <n>` | 固定の日時を n 日目（1 日目 = 2026-10-18）の 08:00 にする（日付をまたぐ UI テスト用） |

### 12.10 App Store に出すための設定

- `PrivacyInfo.xcprivacy` を入れる。`UserDefaults`（難易度の記憶に使う `@AppStorage`）の理由コード `CA92.1` を申告し、収集するデータは「なし」、トラッキングは「しない」。
- Info.plist に `ITSAppUsesNonExemptEncryption = NO`（独自の暗号を使わない）。
- 画面は縦向きだけ（`UISupportedInterfaceOrientations` に portrait だけ）。
- 表示名（`CFBundleDisplayName`）はアプリ名の決定（U-01）まで「ネトレ」。


### 12.11 保存に失敗したとき

- `ReviewStore.recordAnswer` で `context.save()` が失敗したら、`context.rollback()` で今回の追加・変更を取り消してから例外を投げる。成績や復習に、保存できなかった回答は入らない。
- テストで保存を失敗させるため、`ReviewStore.init(context:calendar:save:)` の `save` に保存の処理を渡せるようにする（既定は `{ try context.save() }`）。

### 12.12 画面の細部

- 分野選択（S-02）の ViewModel は `DomainListViewModel`。各行に、分野名・収録問題数（`QuestionRepository.handwrittenCount`）・正答率（`StatsSummary.byDomain`）・今日の復習数（`dueRecords(.domain(d))` の件数）を持つ。
- 出題画面の ✕ のアクセシビリティラベルは「学習を中断する」、入力欄は「回答」。
- テスト用の問題データ（05 §6 の 20 問）には、正解が「0」の問題を入れない（UI テストで「0」を入力すると必ず不正解になるように）。

### 12.13 細部の追加（第三者レビュー 2 回目）

- **間隔の計算の順番**（§3.3）：正解のときは、今の `ease` で `interval` を先に計算し、そのあとで `ease` を上げる。
- **SessionBuilder の引数**（§5.3）：`build(scope:now:calendar:store: some ReviewRecording, repository:rng:)`。§5.3 の `store: ReviewStore` はこの形に読み替える。
- **自動生成の ID の引き直し**（§12.4）：100 回引き直しても重なるときは、その 1 問を入れずに次へ進む（1 回の問題数が 10 に満たなくてもよい）。
- **解説の文**（§5.1）：自動生成問題の解説の「暗算のコツ」には、`CalculationSteps.cidr` が返す文をそのまま使う（考え方だけでなく文言もそろえる）。
- **seed の範囲**（§12.5）：`question(fromId:)`・`subnet(fromId:)` は seed として `UInt64` に収まる 0 以上の整数を受け付ける（0 を含む）。収まらない・数字でない・難易度が 1〜3 でない・種類が違う・区切りの数が違う ID は nil。
- **問題データの検査結果**（§12.3）：`QuestionRepository` は `issues: [ValidationIssue]` を持つ。誤りのある問題（形式違い・正解の誤り）は読み込みから外し、ID が重なった問題は先の 1 問だけ残す。JSON として読めないときは手書き 0 問で `loadFailed = true`。
- **オクテットの読み取り**（§6.2）：空のオクテット（`"192..10.77"`・末尾の「.」）は `.notNumber(index:)`。先頭の 0 はいくつ付いてもよく、値だけで判断する（`"0010"` は 10）。値が 255 を超えるときは `.octetRange(index:value:)`。value は `Int` に収まればその値、収まらなければ `Int.max` で、そのときの文は「第Nオクテットが大きすぎます（0〜255）」。
- **正解の検査**（§12.3）：空の正解、「.」だけの正解、数字と「.」以外を含む正解は `.invalidAnswer`。
- **貼り付け**（§6.2）：`splitPasted` は分ける前に前後の空白を除く。分けられない（nil）ときは、貼り付けた文字をそのままアドレス欄に入れる。
- **問題数が 10 に満たない学習**：QuizSessionViewModel は何問でも動く（進み具合は「n / 総数」、最後の問題で「結果を見る」）。
- **集約の打ち切り**（§6.7）：`SummaryResult` に `extraTruncated: Bool` を持つ（余分な範囲が `extraRangesDisplayLimit` を超えたとき true）。画面は「先頭 256 件を表示」と添える。
- **CIDR 計算の片方が空**（§7.3）：アドレスとプレフィックスのどちらかが空なら `result` は nil（誤りの表示もしない）。
- **分野選択の今日の復習数**（§12.12）：分野の行の数は、その分野の手書き問題の記録だけを数える（自動生成問題は数えない。自動生成問題の復習はホームと成績の数にだけ入る）。
