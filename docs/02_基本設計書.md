## 1. システム構成

```
┌──────────────── iPhone（iOS 17+）────────────────┐
│  NetTre.app                                      │
│   ├ 同梱データ：questions.json（手書き問題）       │
│   ├ 問題の自動生成（サブネット）                    │
│   └ 学習履歴：SwiftData（端末内のファイル）         │
└──────────────────────────────────────────────────┘
        外部との通信なし（サーバー・解析SDK・広告SDKなし）
```

| 項目 | 採用するもの | 理由 |
|---|---|---|
| UI | SwiftUI | 要件（iOS 17+）。片手向けのレイアウトを組みやすい |
| 状態管理 | Observation（`@Observable`） | iOS 17 の標準 |
| 永続化 | SwiftData | iOS 17 の標準。履歴の集計（成績画面）をクエリで書ける。JSON ファイルで保存する案より、件数が増えても扱いやすい |
| テスト | Swift Testing | 引き継ぎ時からの方針 |
| プロジェクト生成 | XcodeGen（`project.yml`） | `.xcodeproj` を Git で管理せずに済み、差分が読みやすい |
| 外部ライブラリ | 使わない | オフライン・プライバシーの要件（NFR-04, 05）と保守の手間 |

## 2. アーキテクチャ

4つの層に分け、上の層から下の層だけを使う。

```
View（SwiftUI の画面）
  ↓
ViewModel（@Observable。画面の状態と操作）
  ↓
Domain（問題・判定・出題順・間隔反復。SwiftUI に依存しない）
  ↓
Data（問題の読み込み、学習履歴の保存）
```

| 層 | 主な型 | 役割 |
|---|---|---|
| View | `HomeView`, `QuizView`, `SessionResultView`, `StatsView`, `SettingsView`、計算機の `CalculatorMenuView` と各計算機の View ほか | 表示と操作の受け付けだけ。判定や計算はしない |
| ViewModel | `HomeViewModel`, `QuizSessionViewModel`, `StatsViewModel`、計算機ごとの ViewModel（`CIDRCalculatorViewModel` など） | 画面の状態（回答前／回答後、入力と結果など）を持ち、Domain を呼ぶ |
| Domain | `Question`, `ReviewState`（既存）、`SubnetQuestionGenerator`（既存）、`AnswerNormalizer`, `SessionBuilder`<br>計算機：`IPv4`・`Subnet`（既存を拡張）、`IPv4InputParser`、`CIDRCalculator`、`SubnetSplitter`、`VLSMPlanner`、`RouteSummarizer`、`RadixConverter`、`CalculationSteps` | 業務ロジック。テストの中心。計算機は入力から結果を返すだけの関数にし、状態を持たない |
| Data | `QuestionRepository`, `ReviewStore` | 同梱 JSON の読み込み、自動生成問題の再生成、SwiftData への保存 |

## 5. データ設計

### 5.1 問題（読み取り専用）

既存の `Question` 型を使う。

- 手書き問題：`Resources/questions.json` に `Question` の配列として持つ（サンプルは `questions_sample.json`）。
- 自動生成問題：保存しない。ID から毎回作り直す。
- 回答はすべて入力式。`kind` は `input` だけを使い、`choices` は持たない（空）。`answer` は正解の文字列 1 つ（例：`"192.168.10.64"`、`"62"`）。
- 選択式のための型と処理（`QuestionKind` の `single`・`multiple`、`Choice`、誤答づくり）は実装工程で取り除く。

**問題 ID の形式**

| 種類 | 形式 | 例 |
|---|---|---|
| 手書き | `<分野の略称>-<4桁の連番>` | `net-fund-0001` |
| 自動生成 | `gen-subnet-<type>-<difficulty>-<seed>` | `gen-subnet-hostCount-2-918273` |

> **変更点（D1・採用）**：引き継ぎ時の ID `gen-subnet-<type>-<seed>` には難易度が入っていない。同じ seed でも難易度が違うと別の問題になるため、ID だけでは問題を再生成できない（FR-06 を満たせない）。そのため ID に難易度（1〜3）を加える。

分野の略称：`net-fund` / `net-access` / `ip-conn` / `ip-svc` / `sec-fund` / `auto-prog`

### 5.2 学習履歴（SwiftData）

| エンティティ | 項目 | 型 | 説明 |
|---|---|---|---|
| `ReviewRecord`<br>（問題ごとに1件） | questionId | String（一意） | 問題 ID |
| | questionVersion | Int | 最後に回答したときの問題の version |
| | domain | String | 集計用に問題の分野を持っておく |
| | isGenerated | Bool | 自動生成問題かどうか（成績で「サブネット計算」を分けるため。v1.4） |
| | interval | Int | 次の出題までの日数 |
| | ease | Double | 易しさ係数（初期値 2.5、範囲 1.3〜3.0） |
| | streak | Int | 連続正解数 |
| | dueDate | Date | 次に出す日（その日の 0:00） |
| `AnswerLog`<br>（回答ごとに1件） | questionId | String | 問題 ID |
| | domain | String | 分野 |
| | isGenerated | Bool | 自動生成問題かどうか（v1.4） |
| | isCorrect | Bool | 正解したか |
| | answeredAt | Date | 回答した日時 |

- `ReviewRecord` は既存の `ReviewState`（構造体）と同じ値を持つ。間隔の計算は `ReviewState.record` に任せ、計算結果を `ReviewRecord` に書き戻す。
- 成績画面（FR-13）は `AnswerLog` を集計する。

## 6. 主な処理の設計

### 6.1 学習の組み立て（`SessionBuilder`）

1回の学習の問題数を N とする（N = 10。要件定義 §4.2）。

1. **復習**：出題範囲の中で `dueDate` が今日以前の `ReviewRecord` を、`dueDate` が古い順に取り出す（最大 N 問）。
2. **新しい問題**：足りない分を新しい問題で埋める。
   - 手書き問題：まだ回答したことがないものを、問題の並び順で取り出す。
   - 自動生成問題：新しい seed（乱数）で作る。種類はランダム。
3. 出題範囲ごとの問題の集め方：

| 出題範囲 | 集める問題 |
|---|---|
| おまかせ（ホームの「学習を始める」） | すべての分野の手書き問題＋自動生成問題（新しい問題のうち半分程度を自動生成にする） |
| 各分野 | その分野の手書き問題のみ |
| サブネット計算ドリル | 自動生成問題のみ。難易度を選べる |

- 手書き問題が足りず N 問に届かない場合、各分野では届いた数だけ出す。0問のときは「この分野の問題はまだありません」と表示する。

### 6.2 間隔反復

- 間隔の計算は既存の `ReviewState.record`（SM-2 の簡略版）をそのまま使う。
  - 正解：連続正解1回目は1日後、2回目は3日後、3回目からは「前回の間隔 × 易しさ係数」日後。易しさ係数を +0.1（最大 3.0）。
  - 不正解：連続正解を0に戻し、1日後。易しさ係数を −0.2（最小 1.3）。
- **次に出す日は日付単位で決める**（D2）。今のコードは「回答した時刻から24時間後」になっており、朝に解いた問題が翌朝の通勤時にはまだ出ない。「今日の 0:00 + interval 日」を `dueDate` にする。
- **自動生成問題の扱い**（D3）：自動生成問題は無限に作れるため、正解したものまで復習の対象にすると、復習の待ち行列がふくらみ続ける。そこで次のようにする。
  - 初めて解いて正解した自動生成問題は `ReviewRecord` を作らない（`AnswerLog` には残す）。
  - 間違えた自動生成問題だけ `ReviewRecord` を作り、復習で2回続けて正解したら `ReviewRecord` を削除する。
- **問題の version が上がった場合**（D4）：履歴（`ReviewRecord`）はそのまま引き継ぎ、`questionVersion` だけ更新する。修正の多くは誤字や解説の補足で、学習の進み具合をやり直すほどではないため。

### 6.3 回答の判定

- 回答はすべて入力式（D5）。`AnswerNormalizer` で次の順に整えてから比べる（今のコードは空白を除くだけ）。
  1. 全角の英数字・記号を半角にする（日本語入力のまま「１１０」と入れても正解にする）
  2. 「,」を「.」にする（`.decimalPad` の小数点キーは端末の地域設定に従い、ドイツ・フランスなどの設定では「,」になるため）
  3. 空白を除く
  4. 英字の大文字・小文字を区別しない
- 正解の文字列が数字だけなら数字のキーボード（`.numberPad`）、数字と「.」だけなら「.」付きのキーボード（`.decimalPad`）を出す。

### 6.4 自動生成問題の品質（既知の TODO の扱い）

要件 NFR-10 を満たすため、次の点を直す（実装工程で対応する）。

| No | 現状の問題 | 方針 |
|---|---|---|
| T-1〜T-3 | 誤答づくり（`makeDistractors`）の不具合と、正解の選択肢を探す強制アンラップ | 回答を入力式にしたため不要。誤答づくりと選択肢の組み立てごと取り除く（v1.1） |
| T-4 | テストがない | 計算式と、生成した問題の正解が計算結果と一致すること・同じ seed で同じ問題になることをテストする |

### 6.5 計算機（FR-16〜24）

計算機は IPv4 のみ（要件定義 U-08）。計算はすべて `UInt32` の整数演算で行い、文字列の加工で計算しない。計算履歴は保存しない（U-09）。入力中の値は、アプリを閉じるまで画面ごとに残す。

**入力の読み取り（`IPv4InputParser`、NFR-13）**

1. `AnswerNormalizer` と同じく、全角を半角にし、「,」を「.」にし、前後の空白を除く。
2. 次の書き方を受け付ける：`192.168.10.77/26`、`192.168.10.77 255.255.255.192`、`192.168.10.77`（プレフィックス長は別の欄で入れる）。
3. 誤りは「どの部分が・なぜ」を返す。例：「第3オクテットが 256 です（0〜255）」「マスクの 1 が連続していません」「プレフィックス長は 0〜32 です」。
4. 入力が変わるたびに計算し直す（計算ボタンは置かない）。

**CIDR 計算（`CIDRCalculator`、FR-17）**

- 既存の `Subnet` を `/0`〜`/32` に広げて使う（自動生成問題は今までどおり `/8`〜`/30`）。
- 使えるホスト数：`/0`〜`/30` は 2^(32−p) − 2。`/31` は 2（両方使える。RFC 3021）。`/32` は 1。`/31`・`/32` のホストの範囲は、全アドレスをそのまま示す。
- アドレスの種別：プライベート（10/8・172.16/12・192.168/16）、ループバック（127/8）、リンクローカル（169.254/16）、共有アドレス（100.64/10）、マルチキャスト（224/4）、予約（240/4・0/8）、それ以外はグローバル。

**サブネット分割（`SubnetSplitter`、FR-18）**

- 分割数 n で指定：新しいプレフィックス長 = p + ⌈log2 n⌉。2 の累乗でない n は、切り上げた数に分かれることを示す（例：5 分割 → 8 分割）。32 を超えるなら誤りとする。
- 必要なホスト数 h で指定：h + 2 以上になる最小の 2 の累乗のブロックにする（h = 1 は /30 とし、/31・/32 は使わない）。
- D6（採用）：一覧の表示は **先頭 256 件まで**。それを超えるときは総数と「先頭 256 件を表示」と示す（/8 を /30 に分けると約 400 万件になり、画面が固まるため）。

**VLSM 設計（`VLSMPlanner`、FR-19）**

- 用途を必要ホスト数の多い順に並べ（同じ数なら入力順）、それぞれ h + 2 以上の最小ブロックを、親ネットワークの先頭から順に割り当てる。大きい順に割り当てるので、各ブロックは自然に境界がそろう。
- 必要なアドレスの合計が親ネットワークを超えるときは、割り当てずに「◯ アドレス足りません」と示す。
- 余った範囲は、CIDR のまとまりに分けて示す。
- D7（採用）：入力できる用途は **50 件まで**。

**経路集約（`RouteSummarizer`、FR-20）**

- 入力の各ネットワークは、ホスト部を 0 にそろえて扱う（そろえたときは「ホスト部を 0 にして扱いました」と示す）。
- 集約ルート：入力の中で最も小さいアドレスと、最も大きいブロードキャストアドレスの、共通する先頭ビットの長さをプレフィックス長にする。
- 余分に含まれる範囲：集約ルートから入力が占める範囲を除いた残りを、CIDR のまとまりで示す。
- D8（採用）：入力できるネットワークは **32 件まで**。

**進数変換（`RadixConverter`、FR-21）**

- D9（採用）：入力の進数は次の順に自動で見分ける。
  1. `0x` で始まる、または a〜f を含む → 16 進
  2. 「.」で 4 つに区切られ、各オクテットが 8 けたの 0 と 1 だけ（または 32 けたの 0 と 1 だけ）→ 2 進
  3. それ以外 → 10 進
- 出力はオクテットごとに区切る（2 進は 8 けた、16 進は 2 けた）。

**解き方（`CalculationSteps`、FR-22）**

- CIDR 計算：区切りが入るオクテット、そのオクテットのブロックサイズ（256 ÷ 2^(そのオクテットのネットワーク部のビット数)）、何番目の倍数か、の順に文で示す。自動生成問題の解説（`blockSizeHint`）と同じ考え方にそろえる。
- ほかの計算機：分割数・ブロックの大きさの決め方を 1〜3 行で示す。

**問題から計算機へ（FR-23）・コピー（FR-24）**

- D10（採用）：S-03 回答後の解説に「計算機で確かめる」を置き、その問題の `IPv4` とプレフィックス長を渡して S-08 を**シート**で開く（学習の流れを途切れさせないため。閉じると解説に戻る）。
- コピーはクリップボードへの書き込みだけ行う（読み取りはしないので、OS の確認は出ない）。

## 7. エラー処理

| 状況 | 対応 |
|---|---|
| 同梱の問題データが読めない（形式の誤りなど） | 手書き問題なしで続ける（自動生成問題は出せる）。開発中に気づけるよう、デバッグビルドではログに出す。リリース前のテストで必ず見つける |
| 学習履歴に保存できない | 学習は続ける。画面の下に「学習記録を保存できませんでした」と短く表示する |
| 学習履歴のデータベースが開けない（壊れた場合など） | 履歴なしで起動する。設定画面から履歴を消して作り直せるようにする |
| 履歴にある問題 ID に対応する問題がない（手書き問題を削除した場合など） | その履歴は出題に使わず、無視する |
| 計算機の入力が誤っている・途中まで | 結果欄は前の結果を消して空にし、入力欄の下に誤りの場所と理由を出す（§6.5）。アプリは止めない |
| 計算の結果が大きすぎる（分割の件数など） | 件数の上限で打ち切り、総数を示す（D6〜D8） |

| NFR-01, 02 | 入力欄・「回答する」・「次へ」を画面下半分（キーボードのすぐ上）に置き、ボタンの高さは 56pt 以上にする。数字のキーボードには改行キーがないため、「回答する」をキーボードのすぐ上に置く（03_画面仕様書） |
| NFR-03 | 問題データの読み込みは起動時に1回だけ。自動生成はその場で計算する（1問 1ms 未満の見込み） |
| NFR-04, 05, 06 | 通信するコードと外部 SDK を入れない。権限の利用目的（`NS*UsageDescription`）を Info.plist に書かない |
| NFR-07 | iPhone 専用（縦向きのみ）。iPad 互換モードでの動作確認を、要件定義テストの項目にする |
| NFR-08 | 標準の文字スタイル（`.body` など）を使い、固定の文字サイズにしない。色はシステムカラーかアセットのカラーセットを使う。入力欄には VoiceOver 用のラベル（「回答」）を付ける |
| NFR-09 | 回答のたびにすぐ保存する（学習の最後にまとめて保存しない） |
| NFR-10 | 計算機の結果は、Python の `ipaddress` で作った照合用データ（数万件）とテストで突き合わせる。照合用データはテストに同梱する |
| NFR-11 | 手書き問題は JSON の追加だけで増やせる。`id` の重複は起動時（デバッグビルド）とテストで見つける |
| NFR-13 | `IPv4InputParser` に入力の整え方と誤りの伝え方をまとめる（§6.5） |
