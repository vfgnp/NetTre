SPACED REPETITION

間隔反復

正解 1 回目　1 日後→ 2 回目　3 日後→ 3 回目から　前回 × 易しさ係数 係数 +0.1（最大 3.0）
不正解 連続正解を 0 に戻して　1 日後 係数 −0.2（最小 1.3）

※ 計算は既存の ReviewState.record（SM-2 の簡略版）をそのまま使う

D2 採用　次に出す日を日付単位で決める

「今日の 0:00 ＋ interval 日」を次に出す日にする
朝に解いた問題が、翌朝の通勤時に出る

D3 採用　正解した自動生成問題は復習に入れない

間違えたものだけ記録し、復習で 2 回続けて
正解したら記録を消す（回答ログには残す）

CALCULATORS 1 / 3

計算機 — 入力の読み取りと CIDR 計算

IPv4 のみ。計算はすべて UInt32 の整数演算で行う。入力は画面ごとに、アプリを閉じるまで残す

入力の読み取り（IPv4InputParser）
全角を半角にし、前後の空白を除く
書き方は 3 通り
192.168.10.77/26　192.168.10.77 255.255.255.192
192.168.10.77 ＋ 別の欄にプレフィックス長
誤りは場所と理由を返す
「第3オクテットが 256 です（0〜255）」
「マスクの 1 が連続していません」
入力が変わるたびに計算し直す
CIDR 計算（CIDRCalculator）
既存の Subnet を /0〜/32 に広げる
自動生成問題は今までどおり /8〜/30
使えるホスト数
/0〜/30：2^(32−p) − 2 ／ /31：2（RFC 3021）／ /32：1
アドレスの種別
プライベート・ループバック・リンクローカル
共有アドレス・マルチキャスト・予約
それ以外はグローバル

CALCULATORS 2 / 3

計算機 — 分割・VLSM・集約・進数変換

計算機計算のきまり設計提案
サブネット分割分割数 n：プレフィックス長 ＋ ⌈log2 n⌉（5 分割 → 8 分割と示す）
必要ホスト数 h：h ＋ 2 以上の最小の 2 の累乗のブロック		D6 一覧は先頭 256 件まで
超えたら総数を示す
VLSM 設計必要ホスト数の多い順に、親ネットワークの先頭から割り当てる
足りないときは割り当てず「◯ アドレス足りません」		D7 用途は 50 件まで
経路集約入力はホスト部を 0 にそろえる
最小のアドレスと最大のブロードキャストの共通の先頭ビット長を使う		D8 ネットワークは
32 件まで
進数変換出力はオクテットごとに区切る（2 進は 8 けた、16 進は 2 けた）D9 入力の進数を自動で
見分ける（次の順）
D9 の見分け方　① 0x で始まる・a〜f を含む → 16 進　② 0 と 1 だけで 8 けた × 4（または 32 けた）→ 2 進　③ それ以外 → 10 進

CALCULATORS 3 / 3

解き方・計算機への移動・照合テスト

解き方（FR-22）

CIDR 計算は、区切りが入るオクテット
→ ブロックサイズ → 何番目の倍数か、の順に文で示す

例：192.168.10.77/26
区切りは第 4 オクテット。ブロックサイズは 64
77 は 64 の 1 倍〜2 倍の間 → ネットワークは .64

自動生成問題の解説（blockSizeHint）と同じ考え方にそろえる

D10解説から CIDR 計算をシートで開く

S-03 回答後に「計算機で確かめる」を置き
問題の値を渡して S-08 をシートで開く
閉じると解説に戻り、学習が途切れない（FR-23）

コピー（FR-24）　クリップボードへの書き込みだけ行う
読み取りはしないので OS の確認は出ない

照合テスト（NFR-10）　Python の ipaddress で作った
数万件の照合用データで、計算機の結果を突き合わせる
